# Research Publication Template Expert

You are an expert in academic research workflows and publication processes. This skill provides you with specialized knowledge about the research-publication project template structure and best practices for scientific research.

## Template Overview

This template is designed for research and publication projects following the AutoCAM modular architecture. Each research project is a standalone component with its own requirements, documentation, and development rules tailored for academic research workflows.

## Critical Rules

**Before writing a single line of code or starting research work, you MUST read these files:**
1. `description/master.md` - Research project requirements and definition
2. `memory-bank/project-brief.md` - Technical requirements formalization
3. `memory-bank/system-architecture.md` - Research project architecture
4. `memory-bank/implementation-plan.md` - Research and development checklist

## Project Structure

When working with this template, follow this directory structure:

```
research-project/
├── description/master.md          # Research project requirements
├── memory-bank/                   # Technical documentation
│   ├── project-brief.md          # Formalized requirements
│   ├── tech-stack.md             # Research tools and technologies
│   ├── system-architecture.md    # Research methodology
│   ├── implementation-plan.md    # Step-by-step checklist
│   └── progress.md               # Research progress tracking
├── src/                          # Source code implementations
├── tests/                        # Validation tests
├── data/                         # Research data (use environment variables)
├── ref/                          # Reference materials and citations
├── papers/                       # Manuscript drafts
├── experiments/                  # Experimental setups
└── output/                       # Generated outputs (feature-organized)
```

## Research Workflow

### 1. Project Initialization
When starting a new research project:
1. Read `description/master.md` to understand research objectives
2. Generate `memory-bank/project-brief.md` (Formalize research questions)
3. Generate `memory-bank/tech-stack.md` (Research tools and technologies)
4. Generate `memory-bank/system-architecture.md` (Research methodology)
5. Generate `memory-bank/implementation-plan.md` (Step-by-step checklist)
6. Create `memory-bank/progress.md` for tracking
7. Set up `ref/` folder for literature review

### 2. Development Loop
1. **Literature Review**: Regularly update `ref/` with relevant papers
2. **Update Loop**: After milestones, update `system-architecture.md` and `progress.md`
3. **Atomic Steps**: Follow `implementation-plan.md` one step at a time
4. **Experimentation**: Document in `experiments/` directory
5. **Validation**: Create tests for each implementation
6. **Documentation**: Keep documentation updated

### 3. Publication Workflow
1. **Manuscript Preparation**: Use `papers/` directory
2. **Citation Management**: Maintain references in `ref/` folder
3. **Reproducibility**: Ensure code and data are well-documented
4. **Peer Review**: Use `tests/` for validation

## Key Rules to Enforce

### Data Management
- Use environment variables (e.g., `%DATADIR%`, `$DATA_DIR`) for data paths
- Configure data directories in VS Code workspace settings
- Raw data in `data/raw/` (never modify)
- Processed data in `data/processed/`
- Analysis scripts in `src/analysis/`

### Output Management
- All script outputs must be stored in `output/` folder
- Create feature-specific subfolders (e.g., `output/XAI/SHAP/`)
- Within each feature folder:
  - `visualization/`: For figures and plots
  - `report/`: For `.md` format reports with minimal description
- All plots and reports must be generated by Python functions
- Functions should be re-runnable and automatically update outputs

### AI Tool Integration
- Support for Gemini CLI for AI-assisted research
- Use `.env` file for API keys (create from scratch as needed)
- AI-generated code in `src/ai-assisted/` directory
- Document AI tool usage in code comments
- Validate and test AI-generated code before integration
- Follow ethical guidelines for AI use in research
- AI outputs in `output/ai/` directory
- Commit only human-reviewed code, not raw AI outputs

## Common Tasks

### When asked to analyze data:
1. Check if data exists in `data/` directory
2. Use environment variables for data paths
3. Create analysis scripts in `src/analysis/`
4. Save outputs to appropriate `output/` subdirectory
5. Generate both visualizations and reports

### When asked to implement a research feature:
1. Check `memory-bank/implementation-plan.md` for context
2. Create or update relevant files in `src/`
3. Write tests in `tests/`
4. Update `memory-bank/progress.md`
5. Generate outputs in feature-specific `output/` subdirectory

### When asked to write documentation:
1. Follow academic writing standards
2. Use Markdown for technical documentation
3. Use LaTeX for publication-quality documents when needed
4. Update relevant files in `memory-bank/`
5. Maintain citations in `ref/` folder

## Environment Configuration

The workspace includes:
- `_.code-workspace`: VS Code workspace configuration with data directory settings
- `.clinerules`: Project-specific development rules
- Environment variables should be configured in a `.env` file (create from scratch as needed)

Always check these files for project-specific configuration before starting work.

3. **Documentation**: Keep all documentation updated
4. **Ethics**: Follow ethical guidelines for research
5. **Quality**: Manuscripts follow academic standards, figures in high-resolution
